## 2. Принятые решения

| Решение | Почему это важно помнить |
|---|---|
| 🟰 Редакционные `GET /api/{articles,news,…}` остаются открытыми. Черновики по ним может прочитать любой, кто знает адрес API (адрес виден в клиентском JS как `PUBLIC_API_BASE_URL`). | Решение владельца. Не поднимать заново как «находку». |
| Читателям и Google — **только дата публикации**, никогда дата создания. | Дата публикации стирается при снятии с публикации и ставится заново при повторной публикации ([publication.ts](../server/src/utils/publication.ts)). |
| Без явной просьбы **ничего не удалять**. | Даже мёртвый код — только предложить одной строкой. |
| Фото дня: отсутствие админского превью черновика — не чинить. | Решение владельца. |

## 4. Открытые пункты

### Безопасность

**4.1 ❌ «От первого лица»: в SEO-разметке нет дат.**
Своя `toIsoDate` ([first-person/[id].astro:63](../src/pages/first-person/[id].astro#L63))
делает `new Date(value)`, а дата из базы приходит объектом `{_seconds}` —
результат `undefined`, поле выпадает. Так было и с `createdAt`, то есть
всегда. Не регрессия.

**4.2 ❌ Можно затереть чужой профиль.**
`createUserProfile` ([userController.ts:110](../server/src/controllers/userController.ts#L110))
берёт `uid` из тела запроса, не сверяет с вошедшим пользователем и делает
`.set()` — полную перезапись. Любой залогиненный, подставив uid админа,
сделает его читателем (роль → `reader`, закладки стёрты) и лишит доступа к
дашборду. Статус: отложено («not yet»).

**4.3 ❌ Можно прочитать чужой профиль.**
`getUserProfile` ([userController.ts:144](../server/src/controllers/userController.ts#L144))
проверяет только, что пользователь вошёл, но не что профиль его. Отдаёт всё:
имя, роль, закладки, а после запуска подписки — `stripeCustomerId` (его пишет
вебхук, [stripeController.ts:104](../server/src/controllers/stripeController.ts#L104)).
Статус: отложено.

**4.4 ⚠️ Stripe верит id из запроса.**
`createCheckoutSession` / `createPortalSession`
([stripeController.ts:17](../server/src/controllers/stripeController.ts#L17),
[:48](../server/src/controllers/stripeController.ts#L48)) работают без входа и
берут `userId` / `customerId` из тела. Вместе с 4.3: прочитал чужой
`stripeCustomerId` → открыл чужую страницу управления подпиской. Уже в
`security-auth-dependency-roadmap.md`, пункт 8. Закрыть до запуска подписки.

### Данные и документы

**4.9 Закладки хранят копию карточки.** Сервер не сверяет закладку с
материалом ([userController.ts:238](../server/src/controllers/userController.ts#L238)).
Если материал сняли с публикации или удалили, карточка остаётся в профиле и
ведёт на 404; если переименовали — показывает старое. Утечки нет, только
устаревшие карточки.

**4.10 `security-auth-dependency-roadmap.md:513` ошибочен.** Там исходят из того,
что открытые редакционные `GET` не отдают черновики. Отдают (раздел 2).

**4.11 Если когда-нибудь закрывать редакционные `GET`:** дашборд читает их
без токена (58 вызовов `list()` / `getById()`), `request()` в
[api.ts](../src/lib/api/api.ts) подставляет токен только для не-GET. Страницы
материалов тоже зовут `getById` анонимно, и на этом держится админское
превью. Всё это придётся научить передавать авторизацию.

**4.12 ⚠️ В ленте главной ещё остались поля, которые карточка не показывает.**
Карточка ленты использует заголовок, рубрику, дату, картинку, ссылку и `paid`
([LandingBody.astro](../src/components/common/LandingBody.astro), блок
`articles-marquee-track`). При этом сервер шлёт и `cardLead` (~5 КБ на 20
карточек), и `subtitleHtml` и др. — остальные не измерялись. Статус: отложено
(«later»). Убирать только из ленты, не из общей `toLandingItem`: её же
используют «Культура» и «Париж».
