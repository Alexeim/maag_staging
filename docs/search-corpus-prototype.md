# Поиск MAAG: состояние интеграции и эксплуатация

Обновлено 24.11.2026. Историческое имя файла сохранено; это уже не только прототип.
Серверная часть работает в облаке для dev-индекса. Поиск в интерфейс сайта ещё не встроен.

## Что где находится

| Элемент | Его задача |
| --- | --- |
| Firestore, коллекции материалов | Единственный источник истины: оригинальные статьи и настройки доступа. Существующие страницы читают материалы через backend, не из Algolia. |
| Algolia | Производная поисковая копия: текст для поиска, поля карточки и ссылка на существующую страницу. Её можно пересобрать из Firestore. |
| Импорт `search:backfill` | Однократно обходит архив и синхронизирует материалы. После завершения не наблюдает за правками. |
| Девять Firestore-триггеров | После записи или удаления документа запускают синхронизацию одной публикации. |
| Firestore `searchIndexSync` | Служебный журнал, без текста статей: версия, аренда, ошибка, срок следующей проверки. Не используется читателями для поиска. |
| `searchVerify` | Каждые 5 минут проверяет созревшие отметки журнала и исправляет расхождения. Это не полный периодический обход всего архива. |

Путь обновления: редактор сохраняет материал → backend пишет Firestore → Eventarc
с доставкой через Pub/Sub вызывает нашу функцию → функция берёт аренду и перечитывает
актуальный документ → готовит записи → обновляет Algolia → освобождает аренду и
сохраняет результат в журнале. Данные `before/after` события не служат источником текста.
Функции не меняют доступ к материалу: они отражают решение редактора.

Будущий путь читателя: запрос в браузере → Algolia → карточки → клик по `href` →
существующая страница материала, которая читает оригинал через backend.
`imageUrl` — только адрес публичной обложки для карточки, не изображение и не поисковое поле.

## Контракт поисковой записи

- Только `published === true` даёт записи. Черновик и удалённый документ дают пустой набор.
- `publicationId = collection/snapshot.id`; `objectID = publicationId#chunkIndex`.
- `sourceVersion` — `snapshot.updateTime` в формате seconds.nanoseconds с 9 цифрами наносекунд.
  Отсутствующий документ всегда имеет версию `deleted`, независимо от времени чтения.
- Каждая сериализованная запись `JSON.stringify` проверяется в UTF-8: максимум 10 000 байт.
  Текст делится по абзацам, словам, затем символам; общие поля учитываются в бюджете каждого фрагмента.
- Открытые записи содержат текст; introduction — только во фрагменте 0.
- Закрытые: title, tags, href, type, access, публичная imageUrl, технические ID/версия/номера фрагментов;
  у интервью публичный interviewee. Нет content, introduction, лидов, mainQuote, подписей и первого абзаца.
  Если цитата уже входит в title, её слова естественно сохраняются в title.
- Публичная обложка: flipper — первый кадр карусели, затем imageUrl; visual-story — imageUrl,
  затем первый слайд; firstPerson/opinion — imageUrl, затем noBgAvatar автора; остальные — imageUrl.
- Только `type === 'first-person'` получает displayTitle: имя автора + сохранённый хвост заголовка.
  Opinion сохраняет title без displayTitle. Профиль читается из `authors/{authorId}`; без имени виден хвост,
  и выдаётся предупреждение. Переименование автора/смена портрета пока требуют ручного sync его материалов.

### Доступ paid

| Коллекции | Значение | Результат |
| --- | --- | --- |
| articles, guides, interviews, flippers, visual-stories | true | закрытая карточка |
| любые | false или поле отсутствует | открытая запись при published === true |
| любые | неожиданное значение (например строка "true", null, 1) | текст исключён, предупреждение |
| news, events, firstPerson, photosOfTheDay | true | текст исключён, предупреждение: штатного гейта у этих типов нет |

`paid` на сайте означает ограничение до регистрации. Поисковый ключ не защищает отдельные поля:
закрытый текст должен отсутствовать в самом индексе, а не только скрываться интерфейсом.

### Настройки Algolia для будущего FE

- searchableAttributes: title → interviewee → tags → unordered(introduction) → unordered(content).
- `attributeForDistinct = publicationId`, `distinct = true`: группировка внутри Algolia, не удаление дублей на клиенте.
- attributesToRetrieve: publicationId, type, href, title, displayTitle, imageUrl, tags, interviewee, access.
- Подсветка title/interviewee; snippets introduction/content по 20 слов. Подсветку нужно безопасно отрисовывать.
- imageUrl и displayTitle не участвуют в поиске. Языковые настройки и синонимы заранее не добавлять.
- Для браузера нужен отдельный search-only ключ с ограничением на dev-индекс. Его подготовка/проверка ещё предстоит.
  Серверный ключ записи браузеру не передавать.

## Журнал и границы восстановления

`syncedVersion` — версия последней успешной синхронизации; `leaseOwner`/`leaseExpiresAt` —
временная аренда одной публикации; `lastError` — причина ошибки; `verifyAfter` — время проверки.
Удалённые публикации остаются в журнале с `syncedVersion = deleted`, из Algolia удаляются.

Аренда 120 секунд, бюджет синхронизации 60 секунд, до трёх кругов перечитывания.
При исчерпании кругов выбрасывается временная ошибка для повтора события.
Дедлайн проверяется также после обхода индекса и после записи отметки перед batch.
Перед отправкой batch сохраняется verifyAfter с окном 10 минут.
Сверка сравнивает фактические objectID/sourceVersion с Firestore, не доверяя syncedVersion журнала.
Слишком большой материал исключается из индекса, понятный lastError сохраняется и после сверки пустого набора.

Это eventual consistency, не мгновенная блокировка текста. Таймаут не отменяет уже отправленный запрос:
старый открытый batch может примениться после новой закрытой карточки. Сверка исправляет такую запись,
но до исправления текст может временно находиться в поиске. После наступления verifyAfter есть ожидание
следующего запуска и очередь (50 за запуск). Принятое допущение: поздние запросы доходят в пределах окна
10 минут. Запись, пришедшая позже окончательного снятия отметки, не гарантированно обнаруживается:
полной постоянной сверки архива нет. Не обещать строгую защиту от произвольно поздней записи.

Локальные значения — в server/.env; параметры функций — в functions/.env.maag-60419
(ALGOLIA_APP_ID и ALGOLIA_INDEX_NAME). Ключ — секрет ALGOLIA_WRITE_API_KEY в Secret Manager.
Никакие `.env*` не коммитить; значения ключей не выводить. Используется существующая служебная запись
953634001415-compute@developer.gserviceaccount.com, новый аккаунт поиска не создавался.
Это техническая запись Google, не второй личный логин владельца.

В server/package.json подтверждены скрипты (первые три по умолчанию только читают):

```sh
cd /Users/dimitrimakarov/Dev/maag_staging/server
npm run search:backfill
npm run search:sync -- --publication articles/<id>
npm run search:settings:dry
npm test
npx tsc --noEmit
npx tsc --noEmit -p tsconfig.test.json
```

`search:sync ... --apply` пишет в журнал и индекс. Backfill с --apply разрешён только для
maag-60419 / IS5SOWASMH / maag_materials_dev, проверяет цель и настройки до первой записи;
каждый ID, включая черновики, перечитывается под арендой. Ошибки перечисляются с ID, код выхода ненулевой.
Не запускать повторный импорт для обычной работы над интерфейсом.

Уже использованный деплой (повторять только по отдельной команде владельца):

```sh
cd /Users/dimitrimakarov/Dev/maag_staging
npx --yes firebase-tools@15.35.0 deploy --only functions:search-sync --project maag-60419
```

predeploy собирает только codebase функций перед его отправкой. Существующие deploy.sh сайта/API
не запускают эту сборку сами. Firebase CLI авторизован владельцем; отдельно ставить standalone-бинарник
через curl не нужно (Intel-бинарник ранее не запускался на Apple Silicon и был удалён).
